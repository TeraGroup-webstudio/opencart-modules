# Очистка каталогу OpenCart (SQL)

SQL-скрипти для OpenCart 3.0.x / ocStore 3.x. Імпортуються через phpMyAdmin. Префікс таблиць визначається автоматично.

> ⚠️ **Перед імпортом зробіть бекап бази:** phpMyAdmin → Експорт → Швидкий → SQL. Видалення незворотне.

## Файли

| Файл | Що робить |
|---|---|
| [`00_cleanup_all.sql`](00_cleanup_all.sql) | Повна очистка: усі товари і всі їхні зв'язки, категорії, характеристики, фільтри, опції, виробники, дані OCFilter, замовлення. Потім прибирає хвости |
| [`00_cleanup_orphans.sql`](00_cleanup_orphans.sql) | Тільки хвости: осиротілі записи після видалення товарів через адмінку (описи, фото, ЧПУ, таблиці модулів). Живий каталог не чіпає |

## Як використати

1. Зробіть бекап бази.
2. Запустіть файл одним зі способів. Файл треба запускати **цілком**.
   - phpMyAdmin → база сайту → **Імпорт** → вибрати файл → **Вперед**.
   - Або вкладка **SQL**: вставити вміст файлу (на сторінці є кнопка «Скопіювати») → **Вперед**.
3. Перевірте вивід. На початку буде знайдений префікс таблиць, у кінці — звіт, що і скільки видалено.
4. Очистіть кеш:
   - `system/storage/cache/` і `image/cache/`;
   - Розширення → Модифікатори → «Оновити».
5. Заново виберіть товари в модулях зі списками («Рекомендовані», слайдери, меню).

**Кілька магазинів в одній базі.** Якщо там кілька установок з різними префіксами, імпорт зупиниться з повідомленням «Префікс таблиць не визначено…» і **нічого не видалить**. Тоді впишіть префікс (як `DB_PREFIX` у `config.php`) у перший рядок файлу:

```sql
SET @p_manual = 'oc_';
```

## Що залишається

- Налаштування, мови, валюти.
- Інформаційні сторінки, банери, модулі, тема.
- Користувачі адмінки.
- Покупці й блог. Їх теж можна видалити: у `00_cleanup_all.sql` розкоментуйте блоки 3 і 4.

## Помилки

| Помилка | Що робити |
|---|---|
| `#1644 Префікс таблиць не визначено…` | Впишіть префікс у `SET @p_manual = '…';`. Нічого не видалено |
| `#1044` / `#1227` Access denied … `CREATE ROUTINE` | Користувачу БД бракує права на процедури. Імпортуйте від користувача з повними правами або попросіть хостинг дати `CREATE ROUTINE` |
| Порожня відповідь або тайм-аут | Використайте «Імпорт» замість вкладки SQL. Повторний запуск безпечний |
| `PROCEDURE … already exists` | Імпортуйте файл ще раз: старі процедури видаляються на початку |

## Сумісність

Перевірено в строгому SQL-режимі на **MySQL 8.0** і **MariaDB 10.6**, на базах у кодуваннях `latin1` і `utf8mb4`:
- чистий OpenCart 3.0.3.3;
- ocStore з таблицями модулів (hpmodel, OCFilter, блог);
- різні префікси;
- дві установки в одній базі.

MySQL 5.7 окремо не перевірявся. OpenCart 2.x не підтримується: там інша схема ЧПУ.
